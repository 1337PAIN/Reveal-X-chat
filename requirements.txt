# Every dependency is pinned exactly, and requirements.lock records the full
# resolved tree including transitive packages. Floor pins (>=) were removed on
# 4 Nov 2026: they had drifted a long way from what the suite was ever run
# against -- numpy>=1.26 was resolving to 2.4, and opencv-python-headless>=4.8
# had crossed a major version to 5.0. A fresh install on a marker's machine
# would not have matched the environment the results in the report came from,
# and the tamper detector is a joblib file, which is sensitive to the
# scikit-learn version it was fitted under.
#
# To reproduce the tested environment exactly:
#     pip install -r requirements.lock
# requirements.txt is the human-edited list; the lock is the generated one.

Flask==3.1.3
# These three move together, and the order they are upgraded in matters.
#
# Flask 3.1 made RequestContext.session a read-only property. flask-socketio
# assigns to it when it hands the HTTP session to a socket handler, so every
# version below 5.7.0 raises
#     AttributeError: property 'session' of 'RequestContext' object has no setter
# the moment an authenticated socket event fires. Upgrading Flask alone turns
# the whole socket suite red (47 failures, 101 errors) while the HTTP tests
# stay green, which makes it look like an application bug rather than a pin.
#
# The earlier note on this block still applies underneath: python-socketio
# 5.10 gave each namespace connection its own sid, and flask-socketio 5.3.5's
# test client still looked packets up by the engine.io sid, so emits went out
# correctly and arrived nowhere. Both constraints are satisfied by the pins
# below.
flask-socketio==5.7.2
python-socketio==5.18.1

numpy==2.5.4
opencv-python-headless==5.0.0.93
Pillow==13.0.0
# 21.2.0 carried two request-smuggling advisories (PYSEC-2026-1433/1434).
gunicorn==26.2.0
argon2-cffi==25.1.0
psycopg2-binary==2.9.13
# 42.0.5 carried seven advisories; 50.0.0 was the first release clear of all
# of them. Re-checked with `python -m pip_audit -r requirements.txt`.
cryptography==50.0.2
# The shipped tamper_detector.joblib was fitted under scikit-learn 1.9.0, and
# this pin has to match it. Loading a joblib model under a different version
# raises InconsistentVersionWarning and is explicitly unsupported upstream.
#
# 1.9.1 was tried on 4 Nov 2026 and reverted the next day: the suite still
# passed, but every server start logged the warning for both estimators. The
# alternative -- refitting under 1.9.1 -- would produce a different model and
# therefore different accuracy, feature importances and confusion matrix from
# the ones reported in the FYP report, so the artifact is what moves last.
scikit-learn==1.9.0
joblib==1.6.0

# Sign-in: Firebase ID token verification and TOTP second factor
firebase-admin==7.7.0
pyotp==2.10.0
